从安装到第一次可验证开发

DevSpace-Forge 把支持 MCP 的 AI 客户端连接到你明确授权的 Windows 或 Linux 开发目录。它的重点不是再提供一个在线 IDE，而是让正在进行的对话能够读取真实仓库、修改文件、运行命令与测试，并把结果带回同一条对话继续判断。Runtime、项目文件、状态与管理入口运行在你自己的机器上；是否把某段文件内容或日志发送给云端模型，则取决于你使用的 AI 客户端与模型服务。

怎样才算安装完成

不要只看安装脚本是否退出成功。至少确认：本地服务健康、Allowed Roots 正确、管理 Console 只在本机可达、MCP 客户端能够完成授权、AI 能打开一个已授权仓库、执行一项小而可回退的修改、运行对应测试并展示最终 diff。完成这条链路，才说明“连接、权限、执行、验证”四个环节都工作正常。

先选择：本地连接还是远程连接

如果你的 AI 客户端和 DevSpace-Forge 在同一台机器上，并且客户端可以直接访问本机 MCP 地址，优先使用本地连接，链路最短，也最容易排错。只有当客户端运行在另一台设备、浏览器云端或远程环境，确实需要从公网访问时，再配置 Cloudflare Tunnel。Tunnel 只是把你自己的 HTTPS 主机名转发到安装器显示的本地 Origin，不替你保存项目，也不是 DevSpace-Forge 的托管服务。

普通单实例安装不需要额外部署 Worker。多实例 Gateway 是独立的高级部署方式，不应在第一次安装时加入问题空间。先让单机链路工作，再根据真实需求增加远程入口或多实例路由。

下载与校验发行包

在 GitHub Releases 下载与你的平台匹配的压缩包，并同时下载对应的 .sha256.txt。Windows x64 使用 ZIP，Linux x64 使用 tar.gz。完整发行包已经包含固定版本的 Runtime、Node.js 与 cloudflared，因此正常安装不要求你另外准备一套 Node 环境。先校验 SHA-256，再解压和运行安装器；这样可以把“下载损坏”和“安装问题”分开判断。

# Windows PowerShell
Get-FileHash .\DevSpace-Forge-vX.Y.Z-win-x64.zip -Algorithm SHA256

# Linux
sha256sum DevSpace-Forge-vX.Y.Z-linux-x64.tar.gz

Windows x64

解压发行包后运行 Setup.exe。第一次安装先选择一个专门用于开发的父目录作为 Allowed Root，不要为了省事授权整个系统盘或整个用户目录。随后选择本地服务端口；如果暂时只需要本机 MCP，就先跳过远程 Tunnel 配置。安装结束后，先确认 Setup 显示的本地健康状态与 Origin，再连接 AI 客户端。已有安装使用较新的 Setup 进入更新流程时，先确认目标实例与活动任务，不要把“检测到旧版本”直接等同于“可以立即覆盖”。

Linux x64

解压 Linux 发行包后，在包目录运行安装脚本。安装器会准备 Runtime、配置与服务，并打印当前实例的本地 Origin、MCP 地址和首次连接信息。默认安装与命名实例的 systemd unit 名称可能不同，因此排错时应以安装器实际输出为准，不要从文档猜服务名。安装完成后先在服务器本机验证 Origin，再继续配置 Tunnel。

./setup-linux.sh

连接 MCP 与 Cloudflare Tunnel

需要远程访问时，在你自己的 Cloudflare 账户创建 remotely-managed Tunnel，并把公开主机名指向安装器显示的本地 Origin。然后在支持 MCP 的客户端中填写完整 HTTPS MCP 地址。示例只使用保留域名，不代表本项目提供公共实例。第一次连接需要完成 Owner 授权；管理 Console 仍然留在 loopback，本地管理地址不能当作公网 MCP 地址发布。

https://workspace.example.com/mcp

如果远程连接失败，先确认本机 Origin 健康，再检查 Tunnel connector、公开主机名和 DNS，最后才检查客户端 OAuth/Owner 授权。不要一开始同时改端口、域名、Tunnel 和客户端配置，否则失败后很难知道是哪一层出了问题。

第一次工作：用一个小改动验证整条链路

连接成功后，不建议立刻让 AI 做大规模重构。选择 Allowed Roots 中一个有 Git 的测试仓库，让 AI 先读取项目说明和 Git 状态，再修改一处容易确认、容易回退的内容，运行最相关的测试或构建，最后展示 diff 与测试结果。这样可以同时验证文件读取、写入、命令执行、工作目录、Git 证据和回传结果是否一致。

对于耗时较长的构建、测试或 Agent 任务，优先使用持久任务能力并保留 job ID。网络断开后先查询状态和日志，不要因为聊天窗口没有继续输出就盲目重跑同一任务。结束前查看最终改动；“命令成功”不自动等于“目标已经实现”，仍要用测试、运行结果或实际页面确认。

Allowed Roots、凭据与数据边界

Allowed Roots 是最重要的访问边界之一：只加入真正需要 AI 操作的目录，多个项目可以放在一个专门的开发父目录下，但不建议把整个 home、用户配置目录或系统目录全部授权。Owner password、Tunnel token、API key、环境变量、私有主机名、真实项目路径和命令日志都可能包含敏感信息，不应提交到公开 Git、Issue、示例配置或截图。

项目工作树保存在本机并不等于所有内容永远不会离开设备。AI 为了理解文件或日志，客户端可能把工具返回的片段发送给你选择的模型服务。因此在处理商业机密、密钥、生产日志或受监管数据前，应同时检查 DevSpace-Forge 的目录权限和 AI 客户端自身的数据政策。DevSpace-Forge 不提供模型额度，也不会绕过客户端的订阅、上下文或使用限制。

按层排错，而不是同时重配所有东西

安装后无法连接时，按固定顺序检查：第一，本机 Runtime/服务是否真实运行；第二，安装器显示的 loopback Origin 是否可达；第三，目标仓库是否位于 Allowed Roots；第四，如启用远程访问，Tunnel connector 与公开主机名是否健康；第五，HTTPS MCP 地址是否正确；第六，Owner/OAuth 授权是否完成；最后再检查 AI 客户端自身的 MCP 支持与网络策略。每一步都保留实际错误、状态码或日志，再决定下一步。

升级后异常时，不要先删除状态目录。确认当前实际运行版本、活动 job、配置与上一个可用版本，再使用发行包提供的恢复路径。更新前保留最近一个已验证可工作的版本，升级后重新做健康检查、MCP 授权、Allowed Roots 与小改动 smoke；只有这些都通过，才把新版本视为完成升级。

FAQ

一定要使用 Cloudflare 吗？

不一定。本地 MCP 客户端能够直接访问本机地址时可以不配置 Tunnel。远程或云端客户端需要可达的 HTTPS 入口时，再使用你自己的 Tunnel 或其他满足安全要求的反向代理。

为什么 AI 看不到某个目录？

先检查它是否位于 Allowed Roots，以及当前打开的 workspace 是否指向正确仓库。不要通过扩大到整个磁盘来解决单个路径问题；修正需要的 root 后重新验证即可。

可以把管理 Console 放到公网吗？

不建议，也不是普通安装的设计目标。公开入口应是受保护的 MCP 路径；管理 Console 保持 loopback-only，需要远程管理时优先使用安全的机器访问方式，而不是把高权限界面直接暴露出去。

安装完成后第一件事应该做什么？

用一个可回退的小仓库做完整 smoke：读取说明与 Git 状态、改一处内容、跑一次测试、查看 diff。不要把第一次验证交给大规模重构或长时间 Agent 任务。
